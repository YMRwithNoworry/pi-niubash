# Pi Niubash 插件开发与 npm 发布计划

## 1. 目标与已确认范围

在当前空目录 `D:/code/pi-niubash插件` 创建可通过 `pi install npm:@paojiao134/pi-niubash` 安装的 Pi 扩展包，使 Pi 的模型 shell 工具及交互 `!` / `!!`、RPC bash 命令统一由 Niubash 执行。

用户已选择 **限定工具入口**：固定 shell 执行入口，禁用独立 PowerShell/cmd 工具，给模型明确的 Niubash 指令；不解析命令文本，不拦截命令中自行启动的子进程。保留 `bash` 工具名称以兼容 Pi、权限插件和现有会话，标签与描述明确为 Niubash。

默认面向原生 Windows、Pi `@earendil-works/pi-coding-agent` 1.2.0 API、Node.js >=22.19.0、外部已安装的 Niubash。Niubash 不随 npm 包捆绑，不自动安装，不存在时不回退到 PowerShell、cmd、GNU Bash 或 WSL。

包名使用已登录 npm 账户下的 `@paojiao134/pi-niubash`，初始版本 `0.1.0`；GitHub 仓库使用 `YMRwithNoworry/pi-niubash`，公开仓库，MIT 许可证。命名在发布前再次查询，若发生占用则使用同账户下可用的相近名称并同步文档。用户已要求 npm 发布，项目约束也要求 GitHub 上传，执行阶段直接完成两项。

## 2. 研究发现与依据

- 当前项目目录没有文件，没有 Git 仓库，需从零创建。
- 已确认本机 Niubash 1.3.3，可用参数为 `niu -c <command>`；`-c` 不加载交互 rc。开发、测试、Git/npm 操作均通过 Niubash，遵守 `C:/Users/Administrator/.pi/agent/skills/niu-only/SKILL.md`。
- 本机 npm 身份是 `paojiao134`，GitHub 身份是 `YMRwithNoworry`；npm 查询 `@paojiao134/pi-niubash` 返回 404，GitHub 查询 `YMRwithNoworry/pi-niubash` 无对应仓库。身份登录不保证发布时无需额外 2FA。
- Pi 文档根目录：`C:/Users/Administrator/.pi/agent/install/releases/1.2.0/node_modules/@earendil-works/pi-coding-agent/`。
  - `docs/extensions.md`：`registerTool()` 可注册工具；`tool_call` 可阻止调用；`user_bash` 返回 `{ operations }` 可接管用户 shell 命令，返回 undefined 会继续到默认执行。
  - `docs/packages.md`：npm 包须声明 `pi.extensions` 和 `pi-package` keyword；宿主依赖放入 `peerDependencies`，不捆绑到 runtime dependencies；Pi 原生可加载 TypeScript 扩展。
  - `docs/settings.md` / `docs/shell-aliases.md` / `docs/windows.md`：内置 `bash` 和 `powershell` 是两个工具；没有内置 cmd 工具；仅改 `shellPath` 无法禁用 PowerShell。
  - `docs/environment-variables.md`：Pi shell 工具应保留当前会话的 `PI_*` 环境变量注入。
- 可复用的公开 API 与持久符号路径：
  - `dist/index.d.ts` 导出 `createBashToolDefinition`、`createLocalBashOperations`、`BashOperations`。
  - `dist/core/tools/bash.js#createBashToolDefinition` 提供 schema、渲染、流式更新、输出截断、临时完整日志、structuredContent 和 PI_* 注入；execute 会采用 `ctx.cwd`。
  - `dist/core/tools/bash.js#createLocalBashOperations` 接受显式 `shellPath`，复用进程启动、超时和整棵进程树取消。
  - `dist/utils/shell.js#getShellConfig`：显式存在的 shellPath 被直接以 `-c` 参数调用；缺失显式路径会报错，因此可以强制指向已解析的 niu.exe，避免默认 shell 探测和回退。
  - `examples/extensions/bash-spawn-hook.ts`、`examples/extensions/sandbox/index.ts` 展示覆写 bash 工具及接管 user_bash 的模式。
  - `dist/core/extensions/types.d.ts#UserBashEventResult` 定义 operations 契约。
  - `dist/core/agent-session.js#executeBash` 应用用户 shellCommandPrefix；TUI 与 RPC 命令分发均会先派发 `user_bash`。直接 SDK `session.executeBash()` 则不自动派发该事件，应在文档中说明此 API 的边界。
- 当前无 Serena 或 FFF 专用工具，源代码研究使用可用的 rg 和定向 read。

## 3. 实施步骤

### 3.1 建立最小 npm / Pi 包

创建：

- `package.json`：ESM、`0.1.0`、Node engines、`pi-package` keyword、显式 `pi.extensions: ["./src/index.ts"]`、npm 发布 files 白名单、公开 scoped 发布设置、仓库链接。
- `src/index.ts`：扩展注册与生命周期。
- `src/niubash.ts`：Niubash 可执行文件解析与共享 BashOperations 的封装。
- `README.md`：中文主文档，含安装、依赖、配置、工具行为、错误排查、实际限制与卸载。
- `LICENSE`、`.gitignore`、`tsconfig.json`、必要测试文件。

以源码 TypeScript 作为 Pi 入口，避免无必要的打包器与编译产物。宿主 `@earendil-works/pi-coding-agent` 使用 `peerDependencies: "*"`，本地开发依赖锁定已验证版本；仅添加 TypeScript、Node 类型及轻量测试运行所需的开发依赖，无额外运行时依赖。不声明旧 Pi 包兼容性，除非实测通过。

### 3.2 解析并验证 Niubash

- 默认通过 Windows PATH 文件查找解析 `niu.exe`，使用 Node 文件/路径 API，不调用其他 shell 查找，不硬编码当前机器安装目录。
- 提供单一配置语义：可用 `PI_NIUBASH_PATH` 指定完整路径，并提供 `--niubash-path` CLI 覆盖；CLI 优先于环境变量，最后查 PATH。支持空格及中文路径。
- 在 `session_start` 或首次实际执行时直接探测解析出的 Niubash `--version`，识别正常 Niubash 输出，不在扩展 factory 内启动进程。
- 解析错误、错误程序、不可启动时保留强制路由并返回可操作错误，禁止退回默认 shell；不写全局 settings.json。
- 使用公开 `createLocalBashOperations({ shellPath: absoluteNiuPath })`，复用 Pi 原生处理，不复制内部进程树代码、不导入私有 dist 路径。

### 3.3 替换模型 shell 与接管用户 shell

- 注册同名 `bash` 覆写，复用 `createBashToolDefinition`，标签、description、promptSnippet、promptGuidelines 显示 Niubash。
- execute 将原始 command 原样交给共享 Niubash operations，命令仅作为 `-c` 的一个 argv，不拼接外层 shell 命令；保留 ctx、signal、onUpdate、structuredContent、错误状态与渲染。
- 指令明确：工具输入直接写 Niubash 命令，不需要再包 `niu -c`；使用原生 Windows 路径；不要依赖 PowerShell/cmd 语法、交互 rc、不存在的 Linux 环境。
- `user_bash` 始终返回同一强制 Niubash operations，覆盖 TUI `!`/`!!` 和 RPC bash；报错也不返回 undefined。
- 模型工具不继承 Pi 旧 Bash 初始化前缀。用户 `!`/RPC 的 shellCommandPrefix 由 Pi 原生行为应用，文档提醒已有 GNU Bash 专用前缀需清理或改成 Niubash 支持的命令；它不改变固定入口的保证。

### 3.4 禁用其他已知 shell 工具

- `session_start` 及每次 `before_agent_start` 将独立 `powershell`、`pwsh`、`cmd` 的已知精确工具名称从 active tools 移除，不改变 read/edit/write 等工具。
- `tool_call` 对上述精确名称始终 block，包含通过 `ctx.executeTool()` / codemode 发起的嵌套调用，防止再次激活后执行；返回清晰错误指向 Niubash bash 工具。
- 不以模糊关键词扫描所有 MCP 名称或停用不相关工具，不增加命令解析器。
- README 明确兼容边界：另外的扩展若同时覆写 bash 或抢先处理 user_bash，可能争用路由；需要避免重复 shell replacement。任意扩展自身的 Node 子进程、外部 MCP 执行器和直接 SDK 调用不属于此插件可全面拦截的工具入口。

## 5. 风险与取舍

- 该包提供 Pi shell 入口路由限制，无法提供操作系统级执行白名单；用户已明确不要求命令文本解析。
- Pi shell replacement 扩展可能相互冲突，必须测试实际注册行为并记录限制，不声称对所有第三方执行器强制生效。
- Niubash 与 GNU Bash 的语言/路径能力存在差异，通过模型工具指令和真实集成测试处理，不使用其他 shell 回退。
- 仅设置 shellPath 不会关闭 PowerShell，也依赖每台机器的本地设置，故不作为完整实现；纯提示词/skill 不能固定执行后端，故不单独采用。
- 不实现自定义进程管理、全局配置重写、Niubash 自动下载、shell 命令黑名单或额外抽象层。
- npm/GitHub 登录已核实，实际发布可能需要 2FA；这是执行阶段外部阻塞的可能性，不是当前计划的待决问题。
